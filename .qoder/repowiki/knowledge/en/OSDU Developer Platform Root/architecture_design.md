The repository is an Azure Developer (azd) application whose `azure.yaml` declares a Bicep provider at `bicep/` and wires pre/post-provisioning PowerShell hooks (`scripts/pre-provision.ps1`, `scripts/post-provision.ps1`, `scripts/settings.ps1`) that glue together the child modules. The provisioning flow provisions AKS/storage/key-vault/Cosmos/App Config via `bicep_infrastructure`, then `provisioning_scripts` bootstraps AD apps and waits for Flux compliance, after which `helm_charts` and `kustomize_deployments` install the platform onto the cluster, while `osdu_schema_registry` registers OFP schemas into the running Schema Service. CI in `.github/workflows/` runs tests, docs builds, release packaging, and web deployment; `docker-compose.yaml` and `.devcontainer/devcontainer.json` provide local dev parity. ARM/Bicep parameter files (`parameters*.json`, `azuredeploy*.json`) drive portal deployments alongside the azd path.
