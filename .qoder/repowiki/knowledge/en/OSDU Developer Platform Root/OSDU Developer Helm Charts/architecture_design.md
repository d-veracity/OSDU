Each subdirectory under `charts/` is an independent Helm v2 application chart (Chart.yaml + templates/ + values.yaml). The charts are organized by concern rather than a single monolith: `osdu-developer-base` provisions shared infrastructure (ServiceAccount, resource limits, Envoy filter, PeerAuthentication, RequestAuthentication, KV-backed SecretProviderClass, storage-share Job); `osdu-developer-service` renders per-service Deployments, Services, Ingresses, HPAs, ScaledObjects, and Istio DestinationRules; `osdu-developer-init` runs one-shot init Jobs (elastic, entitlement, partition, schema, user, workflow); `osdu-developer-auth` deploys the developer auth SPA; `istio-certs` creates a cert-issuing Job and ConfigMap for gateway TLS; `istio-ingress` defines Gateway API Gateways, HTTPRoutes, ReferenceGrants, and certificates; `keyvault-secrets` and `blob-upload` provide Azure CSI SecretProviderClass and blob-upload Batch Jobs; `config-maps` and `storage-volumes` provision shared ConfigMaps and PV/PVCs; `airflow-dags` drives DAG CSV/manifest sync via Jobs. Cross-chart wiring is value-driven: `osdu-developer-base/values.yaml` exposes `azure`, `resourceLimits`, `blobUpload`, and `share` blocks consumed by sibling charts; `osdu-developer-service/values.yaml` declares service definitions (image, path, probes, PVC mounts, env vars, auth bypass) that its templates render into Kubernetes objects. All charts use `_helpers.tpl` for common templating helpers and rely on Azure Workload Identity (`azure.workload.identity/use: true`) for secret access.
