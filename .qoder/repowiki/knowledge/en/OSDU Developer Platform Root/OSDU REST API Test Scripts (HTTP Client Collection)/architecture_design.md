Each `.http` file is a self-contained request collection for one OSDU service area (admin, entitlement, legal, schema, storage, workflow, partition, unit, crs-catalog, crs-conversion, check-*). Files share a common pattern: an initial `POST` to `login.microsoftonline.com/{TENANT_ID}/oauth2/token` with `grant_type=client_credentials` obtains a bearer token, which is then reused via `Authorization: Bearer {{access_token}}` on subsequent requests. Hostnames are parameterized through variables (`{{HOST}}`, `{{HOST_IP}}`, `{{ENTITLEMENTS_HOST}}`, etc.) so the same file can target a local stack (`localhost:8080`) or a deployed environment. Cross-request variable chaining is used extensively (e.g. `@access_token = {{login.response.body.access_token}}`, `@partition = {{getPartitions.response.body.$[0]}}`) to compose multi-step workflows. The README documents the required VS Code `rest-client.environmentVariables` configuration mapping `TENANT_ID`, `CLIENT_ID`, `CLIENT_SECRET`, `AUTH_INGRESS`, `AUTH_REFRESH`, and `DATA_PARTITION`. Sample payloads (`sample.csv`, `sample.las`) accompany ingestion-related scripts.
