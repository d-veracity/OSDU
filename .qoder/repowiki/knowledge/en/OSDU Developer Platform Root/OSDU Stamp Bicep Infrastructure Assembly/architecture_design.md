The top-level `main.bicep` is the single entry point (`targetScope = 'resourceGroup'`) that instantiates a layered stack of Azure resources via Bicep modules: identity, Log Analytics, Insights, Redis, conditional network (blade_network), AKS cluster (blade_cluster), container registry, Key Vault with secrets, storage account, Cosmos DB, partition blade, and GitOps plumbing (flux-extension + flux-configuration). Cross-module wiring happens through module outputs passed as parameters — e.g., `clusterBlade.outputs.clusterName` feeds `fluxExtension`, `keyvault.outputs.name` feeds `storage` and `cosmos-db` secret export, and `logAnalytics.outputs.resourceId` is wired to diagnostics on every AVM module. Blade files under `modules/` (`blade_cluster`, `blade_network`, `blade_partition`, `blade_configuration`) group related resources per OSDU layer, while reusable infrastructure modules live in `modules/<service>/main.bicep`. Conditional deployment (`if (enableVnetInjection)`) gates network vs. default networking, and `dependsOn` blocks enforce ordering across layers (identity → monitoring → network → cluster → storage/database → flux). A Mermaid diagram in `README.md` documents the full dependency graph used by consumers.
