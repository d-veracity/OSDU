The module is centered on `main.bicep` (targetScope = resourceGroup) which declares the Cosmos DB database account and composes child resources via nested modules under `.bicep/`. The entry point accepts arrays of `sqlDatabases`, `gremlinDatabases`, and `mongodbDatabases` to dynamically create per-database instances: `sql_database.bicep` creates `Microsoft.DocumentDB/databaseAccounts/sqlDatabases` and iterates over containers via `sql_container.bicep`; `gremlin_database.bicep` creates `gremlinDatabases` and iterates graphs via `gremlin_graph.bicep`. Cross-cutting concerns are factored into reusable sub-modules: `nested_rbac.bicep` handles role assignments with built-in role name resolution and cross-tenant delegation; `keyvault_secrets.bicep` writes secrets (endpoint, primary key, connection string) into a given Key Vault. Optional features — delete locks, diagnostic settings, private endpoints with DNS zones, and system-partition secrets — are gated by boolean/string parameters so they deploy only when configured. The module exposes outputs for account name, id, location, and system-assigned principal id, and ships `metadata.json` + `version.json` for registry publishing.
