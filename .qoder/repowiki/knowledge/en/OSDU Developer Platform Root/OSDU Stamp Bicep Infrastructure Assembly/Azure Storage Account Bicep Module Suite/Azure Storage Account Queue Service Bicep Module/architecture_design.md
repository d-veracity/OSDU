Two-level Bicep module composition under `bicep/modules/storage-account/queue-service/`. The root `main.bicep` is the entry point: it declares an existing `Microsoft.Storage/storageAccounts` resource by name, then creates a child `Microsoft.Storage/storageAccounts/queueServices@2023-04-01` resource (named `default`) scoped to that storage account. It applies zero or more `Microsoft.Insights/diagnosticSettings` via a typed array parameter (`diagnosticSettingFullType[]?` imported from `br/public:avm/utl/types/avm-common-types:0.2.1`). For each queue supplied in the `queues` parameter array, it instantiates the nested `queue/main.bicep` sub-module with `storageAccountName`, `name`, `metadata`, and `roleAssignments`. The sub-module `queue/main.bicep` reuses the same parent storage account reference, declares the `Microsoft.Storage/storageAccounts/queueServices/queues@2023-04-01` resource, and builds a `builtInRoleNames` map of Azure built-in role GUIDs so callers can pass either role names or full IDs; it then emits a `Microsoft.Authorization/roleAssignments@2022-04-01` per entry scoped to the queue. Both modules expose consistent outputs (`name`, `resourceId`, `resourceGroupName`) and are accompanied by auto-generated `main.json` ARM templates and generated READMEs documenting parameters, resource types, and cross-references.
