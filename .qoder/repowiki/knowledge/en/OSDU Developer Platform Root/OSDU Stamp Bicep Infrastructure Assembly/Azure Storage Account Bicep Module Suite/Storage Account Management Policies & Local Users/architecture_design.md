Two independent, reusable Bicep modules under `bicep/modules/storage-account/`, each targeting a distinct child resource of a pre-existing storage account. The `management-policy` module declares the parent storage account as an `existing` resource and deploys a `Microsoft.Storage/storageAccounts/managementPolicies@2023-01-01` named `default`, passing in user-supplied rules via a `rules` array parameter. The `local-user` module similarly references the parent storage account as `existing` and creates a `Microsoft.Storage/storageAccounts/localUsers@2023-04-01` with configurable authentication flags (`hasSharedKey`, `hasSshKey`, `hasSshPassword`), optional home directory, permission scopes, and an optional SSH authorized-keys list typed by a local `sshAuthorizedKeysType` definition marked `@secure()`. Both modules expose consistent outputs (`name`, `resourceId`, `resourceGroupName`) so callers can consume them uniformly, and both treat the storage account as an external dependency rather than creating it.
