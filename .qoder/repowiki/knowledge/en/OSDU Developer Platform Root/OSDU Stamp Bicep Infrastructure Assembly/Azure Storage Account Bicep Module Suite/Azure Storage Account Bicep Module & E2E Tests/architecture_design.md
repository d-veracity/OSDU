Single-file Bicep module (`main.bicep`) defines the `Microsoft.Storage/storageAccounts` resource along with child resources (diagnostic settings, locks, role assignments) and composes sub-modules for private endpoints (`br/public:avm/res/network/private-endpoint`), management policies, local users, blob/file/queue/table services. Cross-cutting concerns are parameterized via shared types imported from `br/public:avm/utl/types/avm-common-types` (e.g. `roleAssignmentType`, `privateEndpointMultiServiceType`, `diagnosticSettingFullType`, `customerManagedKeyType`). Customer-managed key support references an existing Key Vault and user-assigned identity by parsing their resource IDs. Optional secret export is implemented as a sibling module `modules/keyVaultExport.bicep` that writes account names, access keys, connection strings, endpoints, and SAS tokens into a caller-provided Key Vault; the main module exposes the resulting secret URIs through an `exportedSecrets` output typed as `secretsOutputType`. The `tests/e2e/` directory contains scenario-based deployment manifests under `bicep/modules/storage-account/tests/e2e/<scenario>/main.test.bicep` (defaults, max, blob, block, changefeed, nfs, v1, kvSecrets, system-assigned-cmk-encryption, user-assigned-cmk-encryption, waf-aligned). Each test declares its own RG, optional nested dependencies (in `dependencies.bicep`), and invokes the parent module via a `module testDeployment '../../../main.bicep'` block, typically with an `['init', 'idem']` iteration to validate idempotency. Tests use `targetScope = 'subscription'` and rely on shared diagnostic dependency templates under `utilities/e2e-template-assets/`.
