- Parameters are declared with `@description`, `@allowed`, `@maxLength`, and `@export()` metadata to document and type-module contracts, with sensible defaults that enforce secure baselines (e.g. `allowBlobPublicAccess: false`, `supportsHttpsTrafficOnly: true`, `minimumTlsVersion: 'TLS1_2'`).
- Optional feature blocks are gated by conditional expressions on `kind` or empty collections (e.g. `blobServices` default differs for `FileStorage`, private endpoints loop only when `privateEndpoints ?? []` is non-empty).
- Cross-cutting configuration uses imported AVM common types (`roleAssignmentType`, `privateEndpointMultiServiceType`, `diagnosticSettingFullType`, `lockType`, `customerManagedKeyType`) rather than ad-hoc inline objects.
- Sub-modules are invoked via array-of-object syntax with deterministic `name` values built from `uniqueString(deployment().name, location)` plus a semantic suffix, and parameters are passed explicitly rather than splatted.
- Customer-managed key and secrets-export features reference external resources by parsing `/subscriptions/{sub}/resourceGroups/{rg}/...` paths to extract name and scope, using `existing` resource declarations.
- Each e2e test scenario follows the same shape: declare `targetScope = 'subscription'`, define RG + optional nested dependencies, then deploy the module via a `module testDeployment '../../../main.bicep'` block with an `['init', 'idem']` iteration to verify idempotency.
