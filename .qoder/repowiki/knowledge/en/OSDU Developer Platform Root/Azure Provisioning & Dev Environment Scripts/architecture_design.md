The module is a flat collection of PowerShell entry points invoked by `azd` during the provision lifecycle. `pre-provision.ps1` runs first to validate Azure CLI version (≥2.60), install/update the `k8s-configuration` extension, authenticate via `az login --scope https://graph.microsoft.com//.default`, create or reuse an Azure AD application (`osdu-$AzureEnvName-$SubscriptionId`) with required scopes, register a service principal, and persist `AZURE_CLIENT_ID`, `AZURE_CLIENT_PRINCIPAL_OID`, and `EMAIL_ADDRESS` into `azd` env. `post-provision.ps1` waits for Flux `complianceState == Compliant` on the AKS cluster before disabling App Configuration local auth and patching the AD app's `web.spa.redirectUris` with the discovered public/private ingress endpoints; it also writes `INGRESS_EXTERNAL`/`INGRESS_INTERNAL` back to `azd env` and opens the browser. `settings.ps1` is a developer helper: it resolves the AKS ingress IP, exchanges an `AUTH_CODE` for an `AUTH_REFRESH` token against Microsoft's `/oauth2/v2.0/token`, downloads the Application Insights agent JAR, and renders two artifacts — `src/.envrc` from `envrc_template` (placeholder `%VAR%` substitution) and `.vscode/settings.json` from current `azd env get-values`. `template.yaml` is a hierarchical template keyed by `CORE/<SERVICE>/<RUN|TEST>` whose indented key-value pairs are parsed in `settings.ps1` to emit per-service `<TASK>_<service>.yaml` and `<TASK>_<service>.env` files under `src/<group>/`. Dependency direction is one-way: all scripts call out to `az`, `azd`, and the Microsoft Graph REST API; they never import each other.
