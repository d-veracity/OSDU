Two-layer GitOps layout under `software/` and `stamp/`. Each directory in `software/applications/` (osdu-auth, osdu-core, osdu-reference, web-site) and `software/components/` (global, certs, certs-ca, certs-issuer, osdu-system, mesh-ingress, elastic-search, database, airflow, observability, etc.) is an independent Kustomize package containing a `kustomization.yaml` plus the Kubernetes manifests it composes. The top-level `software/applications/kustomization.yaml` aggregates all application packages, while each component package composes its own sub-manifests (namespace, CRDs, deployments, services, secrets). The `stamp/` directory holds FluxCD `Kustomization` resources (`stamp/applications/kustomize.yaml`, `stamp/components/kustomize.yaml`, `stamp/experimental/kustomize.yaml`) that declare the installation order via `dependsOn`, point to the corresponding `software/*` paths, and attach `healthChecks` against Deployments/StatefulSets/Secrets to drive reconciliation. Dependency direction is strictly bottom-up: `components/global` → `components/certs*` → `components/osdu-system` → `components/mesh-ingress` → `applications/*`, with experimental apps under `software/experimental/` composed separately.
